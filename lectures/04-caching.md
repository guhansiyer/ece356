# Caching, or a brief introduction to Memcached

Databases are fast, but they have limits. MySQL can process around 1M small queries per second on commodity hardware, which might be insufficient for large websites.

Scaling a database across multiple servers is tricky. However, many workloads are read-dominant and can be accelerated by caching query results.

In-memory caching is becoming increasingly cost-effective as opposed to storing cached data on other storage mediums (SSD, hard disk).

## Memcached

`memcached` is an in-memory key-value store for small chunks of arbitrary data (strings, objects) from results of API or database calls, or page rendering.

Assuming a read-dominated workload and high hit ratio, `memcached` can reduced the load on a database server by 10x or better.

There are various mechanisms provided for cache management:

1. Items can be assigned an expiration time by the application.
2. Items can be updated or deleted explicitly by the application.
3. Eviction is implemented using the least recently used (LRU) policy.

## Look-aside vs. Look-through

The L1/L2 cache in a CPU is called a look-through cache because, if we have a cache miss, the fetch from main memory is generated by the cache itself without any work from the application.

`memcached` is called a look-aside cache because the fetch must be issued explicitly by the application.

## Basic API

> Storage

* `set`: adds or overwrites a key-value pair.
* `add`: adds but does not overwrite a pair.
* `replace`: overwrites but does not add a pair.
* `append`/`prepend`: adds data to the value of a pair.
* `cas`: Check-And-Set (Compare-And-Swap), replaces a pair if no one has updated the data since the last read. 
  
> Retrieval

* `get`: retrieves a key-value pair.
* `gets`: similar to `get` but returns a numerical "CAS identifier" to use with the `cas` operation

> Deletion

* `delete`: removes a key-value pair.

### Additional Commands

* `incr`/`decr`: adds/subtracts a positive integer to/from the value of a key.
* `stats`: returns the value of various performance statistics.
* `flush_all`: immediately expires all items in the cache.

## Caveats

> Keys must be consistently named throughout the application.

* A hash function can be used to determine the name of a key or a hierarchical naming scheme can be implemented.

> Loading data from the database to the cache is non-transactional, so data items can be outdated by the time they enter the cache.

* Protect `SELECT` and `set` operations with a lock.

> Slow queries can lead to thundering herds.

* One client goes to the DB while the other waits (similar problem and solution to previous).

> `memcached` is often used to record traffic statistics, like visits to different URLS, but counter values can be spontaneously evicted, making A/B comparisons difficult.

* Pack multiple counters into a key-value pair.
